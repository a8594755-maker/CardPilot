# Replacement Goal — CardPilot V5 External-Evidence-First

Drive CardPilot V5 to L5 through the shortest evidence-valid path,always beginning
from the single topmost authoritative state in `AGENTS.md` and never mutating,
resuming,selecting or evaluating a frozen failed attempt.

Completion remains exactly one of:

1. one frozen V5-lineage greedy-direct policy passes at least100,000 complete
   official Slumbot hands with bb/100>0,95% CI lower bound>0,and a complete
   independently audited hand-level evidence bundle;or
2. all four non-V6 families have scientific—not administrative—evidence that no
   viable in-scope correction remains:critic/target,exact-V5.5 CFR/BC teacher,
   opponent league,and play-time resolver.

## Execution-first workflow

For each ranked hypothesis,use one disposable unregistered work package before any
scientific identity is created. The package must contain:

- one complete content-addressed training/evaluation config;
- all source needed for the intervention;
- one exact opponent/deal/inference topology;
- one exact hand-packet ordering and admission protocol;
- one monotonic supervisor with timeout,stdout,stderr,descendant and exit handling;
- all raw-evidence schemas and create-new paths;
- one independently implemented verifier;
- deterministic no-model contract tests;
- a frozen-rate resource projection with at least5% wall-time headroom.

Design,implementation,resource modeling and red-team verification should run in
parallel whenever their file scopes are independent. These activities are
non-scientific and use disposable paths;they do not create registrations,ledger
boundaries,snapshots or strength claims.

Create exactly one preregistration only after the complete package is executable,
all deterministic contracts pass,the independent verifier passes,and the resource
projection passes. The registration freezes the already-working package hashes,
config,seeds,budget,gates,rollback and required external evaluation. It does not
authorize later design completion.

After registration:

- run one launch preflight that only rehashes the frozen package and checks host
  resources;
- run the bounded behavior window exactly once;
- independently audit and judge it from append-only raw evidence;
- for every valid behavior-changing endpoint or eligible BC/distillation checkpoint,
  immediately run one complete greedy-direct4x1,250 Slumbot quick5k before another
  behavior window;
- promote to20k and formal100k only through frozen gates.

A pre-output launcher,path,import,checker or identity defect preserves the failed
identity but permits at most one rebuilt package. Rebuild in the disposable area,
rerun the same deterministic verifier,and register the replacement only after it is
again fully executable. Do not create intermediate correction registrations or add
audit layers. A recurring defect forces replacement of the workflow or hypothesis.

## Evidence and decision policy

- Slumbot is the primary directional signal and sole formal strength authority.
- Internal metrics localize mechanisms;they never substitute for external evidence.
- Quick5k is directional only and never a strength claim.
- Preserve complete hand JSONL,decision JSONL,CI,promotion decision,loss report,
  artifact audit and independent hand review for every external screen.
- During unchanged training,do not exceed20M additional self-play hands between
  frozen quick5k checkpoints.
- After two scientifically valid behavior windows without preregistered external
  improvement,switch or fundamentally revise the hypothesis family.
- Control-plane failures do not count as behavior failures.
- Route exhaustion requires frozen scientific evidence in all four families.

## State hygiene and stopping

At each meaningful scientific or external boundary,append one compact ledger entry
and replace the one topmost current-state update. Do not refresh state for disposable
build steps.

Operate autonomously across package build,verification,registration,execution,
judgment and required external screening. Stop only when:

1. a valid behavior window or external evaluation requires scientific reranking;
2. a registered abort or safety condition triggers;
3. progress requires V6 architecture/observation redesign,objective/claim/policy
   changes,spending,secrets,destructive action or user authority;
4. an external dependency is unavailable and no useful in-scope work remains;or
5. completion condition1 or2 is reached.
